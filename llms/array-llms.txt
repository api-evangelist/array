# Array

> Array is an embedded fintech products platform that lets financial institutions, fintechs, credit-service companies, and consumer brands integrate consumer credit, identity, and background data into their own user experiences and marketing funnels via embeddable white-label components, private-label experiences, and APIs.

This llms.txt was generated by the API Evangelist enrichment pipeline from Array's public surface: array.com, Array's public embed loader at embed.array.io, live anonymous responses from the Array API at array.io, and Array's Statuspage JSON API.

Array's developer documentation at docs.array.com is password-protected at every path (it returns HTTP 200 serving ReadMe's "Password Protected" form). Array advertises an OpenAPI specification, a Postman collection, sandbox identities and sample credit reports on that site; none of them are publicly reachable, so none are included here.

## API

- [Array API (production)](https://array.io/api): REST API for credit, identity and background-data products. Confirmed live — `/api/user/v2` and `/api/report/v2` return structured JSON errors to anonymous callers.
- [Array API (sandbox)](https://sandbox.array.io/api): Host-for-host sandbox mirror of the production API.
- [Developer Tools](https://array.com/developers): Public overview of Array's developer resources.
- [Developer Documentation](https://docs.array.com): API reference, OpenAPI and Postman collection — password-protected.

Authentication is by API key: a 36-character `appKey` identifies the application, `x-credmo-user-token` carries a consumer token from the end user's device, and `x-credmo-client-token` carries a server-side client token. Errors are plain `application/json` with a `message` field and, on validation failures, an `error[]` array of `{value, message, param, location}`. There is no OAuth, no OpenID Connect, and no published rate limit.
